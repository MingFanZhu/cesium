## Source facts

`LegacyInstancingStageVS` 的乘法顺序为 model × components.transform × instance ×
axisCorrection × nodeHierarchy × vertex。`getPositionMinMax` 在 primitive 空间加实例平移，
`ModelDrawCommands` 再使用含节点矩阵的 modelMatrix 变换整球；node scale 错误作用于实例间距。
`ModelDrawCommand.modelMatrix` setter 会再次使用同一错误范围，模型总包围体同样受影响。
普通 EXT_mesh_gpu_instancing 的 GPU 顺序不同，不能共用这个修正。

## Design and steps

1. 先用内存生成的 i3dm / GLB 复现小 node scale、远间距实例的漏绘，保留失败证据。
2. owned helper 在 I3dmLoader 已准备的 Float32 TRS 上计算 3×4 affine 系数的上下界，
   固定 24 个 Float64 值（192 bytes），共享给 GLB 多节点的 instances copy。
3. 当前节点的真实八角点先应用 axis/node，之后通过实例系数区间求保守 AABB；
   绘制球只在最后应用 tile / RTC，与 GPU 顺序一致。不保留逐实例 CPU 副本、不改 Shader。
4. 初始 draw、模型/节点矩阵更新、模型总范围使用同一 helper。原生 draw modelMatrix 不变，
   派生命令继续共享球对象。SCENE3D 外保留原生流程，不扩宽当前引擎场景模式。
5. Specs 验证实例间距不随 node scale 缩小、非均匀/零/负缩放、旋转、父节点、轴修正、
   RTC 和外层变换；真实 GPU 渲染、镜头转动、拾取、更新与销毁；回归受影响原生套件。
6. 检查 SGP、静态格式和类型，记录开销及保守范围限制后提交本地 checkpoint。

## Boundaries

区间聚合忽略不同实例系数之间的相关性，会扩大范围，但不会裁掉合法实例。
每次变换更新的工作量只随 primitive 数量变化，不随实例数变化；加载时 O(instances)。
普通 glTF、EXT instancing、View 视锥策略、渲染状态和几何保持原路径。

## Results and handoff

- 已复现：node scale 为 0.01、实例相距 1000 m 时，原绘制球半径仅约 6.083 m；
  镜头小幅旋转出现黑色像素及无深度拾取。修复后范围覆盖两个实例且转动镜头持续可见。
- 实现与计划一致：4 个最小上游接入点，全部登记 SGP-0075；helper 和测试均为自有文件。
- ChromeHeadless 真 WebGL 严格检查下 4 个专用用例通过，包含像素、深度拾取、
  父子节点/tileset 变换、矩阵实例属性、球面 ENU 数学包含性及销毁。
- 原生 I3dmLoader 19、ModelDrawCommand 44、ModelMatrixUpdateStage 5 全部通过；
  ModelSceneGraph 17 通过，1 个 Fog 断言失败。InstancingPipelineStage 因 2D 初始化
  被当前 deferred 产品契约拒绝，无法进入用例。两类失败均已恢复修改前的 4 个接入文件复现。
- 开发 ESM / IIFE / CJS 构建、`npm run tsc`、定向 ESLint / Prettier、Markdown 检查
  及 upstream audit 通过。`gulp prepare` 因现有安装缺少 `draco3d/draco_decoder.wasm`
  未通过；未改变依赖，已准备的资源足以完成上述真实渲染与构建验证。
- 100,000 个平移实例的摘要捕获约 14.67 ms；10,000 次变换更新合计 12.81 ms，
  约 1.28 μs/primitive/update（Node v24.9.0，Intel i5-12490F，暖机微基准，非整帧耗时）。
  每份摘要固定 192 bytes，无新增 GPU 资源。
- Architecture/code review approved，见关联 review；无下一阶段或待实施项。
