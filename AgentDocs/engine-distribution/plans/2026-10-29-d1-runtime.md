## Source facts

`buildEngine` generates shaders/barrels; `buildWidgets` generates its barrel.
`buildCesium` generates the common root barrel, bundles CSS/Workers/assets and calls
`bundleCesiumJs`. The latter hardcodes IIFE global/file names. ESM already preserves
`import.meta.url`; Core/buildModuleUrl falls back to Cesium.js script discovery.
`buildTs` generates and validates the combined ambient cesium declaration using
tsd-jsdoc plus existing fixes. The graph predates some build helpers; inspected source
after graph search/trace returned insufficient build/template coverage.

## Design and steps

1. Add only an optional IIFE global name to existing bundling and forwarding options,
   default Cesium. Owned CLI composes native builders with SceneGIS target options.
2. Recognize SceneGIS.js and SCENEGIS_BASE_URL in existing URL implementation; new global
   precedes legacy global, remaining resolution and Worker protocol unchanged.
3. Generate standalone ESM/UMD declaration from the existing generated combined
   declaration with TypeScript AST; emit package metadata and index declaration shim.
4. Copy all runtime resources and licenses using existing helpers, with owned delivery
   orchestration. No source rename, engine copy, generated Git changes or SDK edits.
5. Focused URL Specs, exported value/declaration parity, browser native Worker/real
   WASM/texture loads, root/subdirectory IIFE/ESM Globe/Planar creation and destruction.
6. Retained Cesium development/release builds, type generation/checks, SGP audit, review,
   update handoff and Chinese local commit checkpoint.

## Exit and risks

Both globals resolve documented resource roots and both package access forms compile.
Only public declared values are compared to runtime: native soft-private runtime exports
remain outside public docs/types as before. Inline Worker names are implementation
details and remain CesiumWorkers/CESIUM_WORKERS. D2 documentation is not active yet.
