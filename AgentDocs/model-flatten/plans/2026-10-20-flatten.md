## Objective and boundaries

Implement an explicit CustomShader subclass for mesh 3D Tiles, using local meter
XY polygons with direct holes and a local target Z. Globe uses an explicit ENU
frame; Planar uses an explicit Cartesian frame. No implicit CRS or ellipsoid
height conversion. Keep native content scheduling, IDs and material textures.
SDK integration follows owner visual acceptance and is outside this task.

This is vertex deformation, not triangle clipping, mesh editing or data export.
One immutable polygon/frame per shader, up to 256 edges; height and enable are
mutable. Static triangle mesh is the qualified profile. Animated, legacy i3dm,
classification, native 2D and unrelated CustomShader composition are outside it.

## Source facts and design

- ModelVS calls CustomShader before geometryStage. TextureUniform supports float
  typed arrays. Owned GLSL uses the existing ADR-0030 generator.
- Uniform callbacks see each command's UniformState model matrix. Compose the
  model-to-local frame on CPU in double precision, including node/tile transforms;
  do not subtract ECEF coordinates in GLSL or cache the main camera for shadows.
- Reuse the owned planar polygon geometry's topology validation/normalization.
  Store edges in a fixed RGBA32F texture. AABB early rejection, then even-odd
  crossings with explicit outer/hole boundary policy. No per-frame triangulation.
- Correct affected triangles' geometric normals in CustomShader's material stage.
- SGP-0064 calls owned helpers from Cesium3DTile bounds access and
  ModelDrawCommand submission. Preserve original volumes; conservative union of
  source sphere and its projection sphere covers partial deformation. Native
  traversal/SSE uses conservative volumes; no alternate scheduler.
- Disable/replacement restores original bounds. Shader textures are caller-owned;
  detach/destroy consumer before destroying the shader.

## Validation and completion

Specs: polygon validation, holes/concavity, snapshots, frame validation, bounds
outside old volume, restoration and default path. GPU E2E: deterministic mesh
with nested transforms, globe/planar large coordinates, depth picking inside,
outside and holes, height changes, disabled restoration, true tile/command
culling, resource stability. Local photogrammetry example for visual inspection.
Full build/release, types, focused upstream Specs, lint and patch audit.
Record bounded warm CPU measurements; no universal FPS claim.

## Results

Implementation and automated qualification complete. Remaining owner visual
acceptance is carried by [inverse maintenance](2026-10-22-inverse.md) and the
extension index; SDK integration is not started.

- Public CustomShader subclass, bounded float edge texture, precise frame
  composition, deformation normals and conservative tile/draw bounds implemented.
- Invalid rings/frames and known incompatible primitive modes fail explicitly.
- Seven owned Specs and 73 focused upstream Specs passed. Four development and
  four minified release GPU scenarios passed across globe and planar worlds.
- Tests cover nested transforms, direct holes/concavity, independent picking,
  height movement outside original culling bounds, enable restoration, fine/coarse
  LOD, texture stability and destruction. Real photogrammetry rendered in both worlds.
- Full development/release builds, generated declarations, TypeScript, scoped
  ESLint and patch audit passed.
- Texture allocation is 8,192 bytes per instance, with no extra draw pass. A
  release warm-cache benchmark measured approximately 0.1 ms at p95 for 100 bounds
  queries in both worlds; median was below timer resolution. This measures CPU
  lookup overhead only, not vertex shader cost or a general FPS guarantee.
- Widened native filtering exposed existing deferred/non-3D restrictions and five
  old color expectations. All five color failures also reproduced with the two
  integration files restored temporarily to HEAD. See review for exact scope.
- Global AgentDocs markdownlint passed. Global formatting has 507 existing
  failures outside this extension; changed extension documents pass.

No SDK code, source mesh topology, builtin model GLSL or scheduling algorithm was
modified. Cross-boundary slopes and LOD boundary differences remain explicit
prototype limits for owner acceptance.
