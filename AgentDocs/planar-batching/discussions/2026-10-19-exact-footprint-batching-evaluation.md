## 结论

可以进一步放宽，但一般的 polygon/polygon 不相交判定不能直接代替现有 bbox 判定。
CPU 分层与 GPU 片元归属必须同时正确。凹面和孔洞的常见情况需要改进后者；只有较窄的一类
“bbox 交叠区域在双方轮廓中均为空”可保持当前 Shader 合批。
本轮只做源码分析、隔离实验与测量，不激活下一 phase，不改变既有渲染行为。

## 已复现的 GPU 限制

`SceneGISPlanarGroundAreaFS.glsl` 用地表深度重建坐标，并仅做每实例 XY extent discard。
Stencil 记录本组所有闭体的覆盖总和，不保存覆盖来自哪个业务对象。
当 bbox 相交时，A 的投影闭体片元可能在 B 的真实地表范围内通过 A 的 extent 判断，
消费 B 建立的 stencil 并写入 A 的颜色和 ID。CPU 证明 A/B 轮廓不交不能阻止该行为。

在独立浏览器 harness 中仅将两个已知不相交对象的 command ranges 强制合并，保留产品源码、Shader 和 VA：

- 凹 L 面和其凹槽中的小面、方环面和孔洞中的小面，均使用红/蓝半透明颜色。
- Chrome Headless 155，1000×800，地表为零高程、volume envelope 为默认 ±1 m。
- 90°、45° 俯角时中心样本正确；25°、15° 时小面的 ID 从 `island` 错为 `outer`，
  RGBA 从 `[73,88,208,255]` 错为 `[197,88,104,255]`。现有分组在全部这些角度正确，页面错误为零。
- 此实验只证明直接合并不成立；不得据此加入俯角阈值。

## CPU 构建测量

Windows、i5-12490F、Node 24.9.0。最终 CPU 测量单独运行，预热各算法后每项另预热 3 次、测 9 次取中位数。
使用当前 PolygonGeometry 的已验证 rings 和已生成 topTriangles，几何构造不计入分组时间；
每次分组重新建立所需缓存，因此包含候选检查、缓存准备和分层成本，不是 warm frame 或完整 GPU 构建时间。

比较三种原型：现有 RBush bbox 分层；边界线段检测加外环/孔洞包含判断；复用三角剖分并建立 triangle RBush、做 triangle SAT。
环方法缓存边的 bbox，对 boundary contact 保守判为冲突。原型尚未覆盖所有浮点退化与共边语义，不能直接作为产品实现。
精确原型未沿用仅凭 bbox 包含删除前驱的优化，以免丢失真实轮廓约束。

除双方交叠区域均为空的情况外，不能用当前 Shader 安全兑现。拾取分组受同样限制。
零候选样本的亚毫秒差异属于测量/JIT 波动，没有几何精确检查收益。

低顶点、低相交候选密度的成本可控；高顶点曲线轮廓及密集 bbox 候选会明显增加同步构建时间。
本次高顶点圆环样本的现有 geometry 构造另需约 203 ms，精确环判定在其上追加约 32 ms，不能混为每帧开销。
完全重叠用例有 523,776 个候选，说明不可直接取消包含剪枝后对所有对象默认启用通用精确判断；
该耗时不是算法下限，矩形、相同几何或已证明包含关系可以保留专门的快速路径。

## 两条候选路径

### 保持当前 Shader 的安全放宽

令 `R = bbox(A) ∩ bbox(B)`，只有 A 和 B 的实际填充轮廓在 R 中都为空时才允许合批。
等价于 `polygon(A) ∩ bbox(B)` 和 `polygon(B) ∩ bbox(A)` 都为空。
此时一个对象的 extent 不可能接收另一个对象的真实覆盖片元，仍可使用已有 stencil/extent 协议。
用边界检测和含孔包含判断检查 polygon/rectangle，比检查全部 polygon/polygon 更窄。

512 对向外的 L 面样本：分组原型约 1.70 ms，命令 4 → 2；两个面内部与 bbox 交叠空区的
RGBA/ID 在 90°、45°、25°、15° 下与现有独立分组相同。
普通凹槽内小面、孔内小面和嵌套环不符合这个条件，仍保持原来的 4/32 条命令。

### 支持一般轮廓不交，需要同步改 GPU 归属

可研究复用现成 topTriangles，为 color/pick 增加三角形或凸片的精确地表范围判断，覆盖凹面和孔洞。
若简单改成逐三角形闭体，原有 `2V` 顶点、`2T+2V` 三角形会变为 `6T` 顶点、`8T` 三角形。
复杂面中通常约增加到 3 倍顶点、2 倍三角形；还需增加精确边界 attributes，并验证接缝和共边。
这是几何计数推导，本轮没有实现该 Shader，也没有测得 GPU 净收益。

另一种 per-instance 环数据加 fragment point-in-polygon 可避免拆成大量闭体，但引入额外数据上传、
动态边遍历与片元成本，不能只凭 draw 数更少就认定更快。

两条路径都必须重新证明前驱删除规则。仅有 `bbox(new)` 包含 `bbox(old)`，并不证明新轮廓覆盖旧轮廓；
例如旧面一部分落入新面的孔洞，后续面仍可能只与旧面相交。不能照搬 B5 的 bbox 支配剪枝。

## 建议与交接

不建议现在全量替换为通用精确 polygon 相交判断。优先以业务数据统计 bbox 假相交导致的层数增量，
而不是只统计假相交对象对数量；本轮多数样本已经仅 4 条命令，再省 2 条未必抵消复杂 GPU 路径成本。

如后续要求继续实现，先建立新的 phase，优先验证“双方 bbox 交叠区域均为空”的安全放宽。
若真实数据有大量嵌套环带或多层 bbox 假相交，再单独评估精确 GPU footprint 路径及总 GPU/CPU/内存收益。
空间判定只在静态拓扑构建时执行，缓存与属性改色/显隐解耦；不增加俯角开关。
本轮无产品改动，upstream-owned files=0，SGP=None；既有 B5 checkpoint 保持。
