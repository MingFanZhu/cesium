## Objective

建立私有观察点深度捕获，输入独立 Camera 和显式候选命令，
产出可供后续重投影比较的深度纹理；先验证渲染语义和资源隔离。

## Non-goals

本阶段不发布公开 API，不把主 commandList 当成完整数据选取，
不实现 terrain / tileset 调度，不声称完整产品就绪。

## Entry conditions and current source facts

`DerivedCommand.createDepthOnlyDerivedCommand` 保留原始 VS，并在有 discard /
depth write 时保留 FS。`createLogDepthCommand` 使用原生 log-depth 公式。
`FramebufferManager` 支持 depth-only target；`PassState` 可独立指定 viewport。
原生命令可能携带 framebuffer、scissor、stencil 和 camera-dependent uniforms，
必须在实际 GPU 测试中检查，而不是只检查源码字符串。

## Detailed design

私有 `_SceneGISViewshedDepth` 显式接收 Scene 并拥有深度目标、PassState 和
实例级 WeakMap 派生缓存。捕获仅接收明确候选的 opaque / MASK 命令，
按观察点 frustum 独立剔除；共享原 VA / uniforms / ShaderCache。
采用原生 log-depth 及 depth-only 派生，不改写模型顶点或材质逻辑。
捕获结束（包括异常）恢复主 UniformState 的 camera / frustum / pass。
资源由实例释放；resize 替换旧目标；不接管候选 command 或 model 生命周期。

## Steps

1. 独立深度 target、命令派生、相机状态恢复。
2. GPU 验证变换、alpha discard、不同观察点、主相机移动与异常恢复。
3. 测量 warm pass 资源复用 / draw 数，完成自审与 checkpoint。

## Validation

真实 WebGL2 Specs 验证中心 / 边缘深度、原生 log-depth 解码、
后续显示命令不被观察点 camera 污染、resize / destroy 释放、
两个实例不共用结果。运行 build、相关 ESLint / prettier 和类型检查。

## Risks and dependencies

保留 FS 的 depth-only shader 可能仍含 MRT 或 lighting uniform，
以真实 GPU 检查确认兼容性。Camera-dependent Model 状态的完整更新在 V2 接入。
本阶段不增加公有能力，不把 private helper 测试当成集成验收。

## Completion criteria

上述直接 GPU 与生命周期验证通过，review 无未解决阻塞项并创建独立本地提交。

## Deviations and results

实现完成。捕获同时屏蔽主视图 TAA jitter 并在 finally 恢复；
保留真实的主多视锥 near / far，不能仅恢复 Camera 的整个 frustum。
主视图 framebuffer、stencil、scissor 和 viewport 不沿用。

5 项真实 Chrome Headless 155 / Windows WebGL2 Specs（启用 webglValidation）
全部通过：大平面坐标 / ECEF 的顶点变换与 discard，实例隔离、主相机移动、
warm target 复用、resize / destroy、异常恢复（含 jitter / 子视锥）、
独立 bounds 剔除和透明内容排除。最小场景每次捕获 1 draw；
warm 不创建新的 target，隐藏 / 剔除后 0 draw。
完整 `npm run build`、focused ESLint / prettier / markdownlint 通过。
全 AgentDocs markdownlint 通过；全 AgentDocs prettier 仍有原有 524 个文件警告，
本扩展 scoped prettier 通过，未改写其他扩展。

没有 upstream-owned 修改或 SGP。此阶段无新 GLSL，复用原生深度派生。
剩余产品集成风险进入 V2，V1 private helper 不宣称 streaming / readiness 完成。
