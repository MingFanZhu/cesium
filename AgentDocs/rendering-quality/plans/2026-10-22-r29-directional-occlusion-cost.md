## Source facts and scope

The paired R28 estimate adds about 0.2 ms, but whole-frame elapsed time includes
CPU submission and many full-screen light draws. A fresh CPU profile of Bistro
reproduces 627 group replacements and 627 ShaderCache source lookups per frame,
with ShaderBuilder/build/cache dominating sampled CPU time. Both scalar and
directional modes exhibit the same group churn.

`prepareGroups` partitions by owner and lighting defines. It compares a group's
source uniformMap before checking `seen`, so another primitive in the same model
can invalidate an already-selected group. Material capture later resolves only
the final map entry for that owner/key; the earlier light groups are redundant.
Native per-primitive material values have already been captured in the G-buffer;
light uniforms generated by the native pipeline are model-level. Preserve their
paired generation and invalidation for real pipeline changes (Viewshed V3 fix).

Select each model/lighting-key group once per frame before comparing its native
uniformMap. Keep extension-layout / EDL / first-source binding changes effective
across frames. Preserve native material capture, group IDs, lighting output,
SSR/clearcoat, clipping/style, explicit IBL, shadows and all resource owners.
Do not lower sample count/resolution, approximate the accepted cone shader,
change defaults, or optimize unrelated opaque grouping without evidence.

## Steps and bounded evidence

1. Preserve fresh scalar/directional images and timings for both worlds; sample
   CPU call stacks and allocation/replacement counts separately from GPU elapsed.
2. Reproduce the duplicate-group issue with a real multi-primitive glTF Spec.
   Fix the scheduling order and check ordinary / directional group reuse, native
   dynamic uniforms, IBL branch rebuilds, visible command order and lifetime.
3. Rerun shared DeferredLighting + AO/SSR integration as relevant. Match old/new
   pictures with fixed light/camera/exposure; check SSR/SSIL coexistence and motion.
   Record actual material/light draws, resources and scalar/directional times.
4. Verify normal/release shader products and scoped lint, update review and ADR,
   record the owner acceptance and checkpoint separately from R28. No public API
   or new shader algorithm means no speculative full-suite expansion.

## Gate

Accepted picture and native updates remain correct. Actual redundant CPU/draw
work must decrease in the reproduced scene; report the remaining incremental cost
honestly, including device/session noise. Keep screen-space limitations and default
off. Stop after bounded sufficient evidence; this is not a new renderer rewrite.
